# Karma Contributor — V1: Telegram Mini App без бэкенда

## Идея продукта

Приложение для трекинга добрых дел с геймификацией. Пользователь записывает совершённое дело → получает баллы кармы → растёт в уровнях.

V1 — это полноценный личный трекер: без аккаунтов, без бэкенда, без верификации со стороны других людей. Всё, что нужно, — записать дело и увидеть, как растёт карма.

Верификация дел другими людьми, лидерборды и общий рейтинг — это [V2](./v2-reviews.md).

## Ключевые решения

- **Приложение живёт внутри Telegram как Mini App** с самого начала. Веб/PWA-режима нет: ни service worker, ни манифеста, ни install-промпта — оболочку целиком даёт Telegram.
- **Бэкенда нет.** Данные хранятся в **Telegram CloudStorage** — KV-хранилище, привязанное к аккаунту пользователя.
- **Эвристика баллов и кривая уровней — отдельный изолированный модуль.** В V2 этот же код переиспользуется на сервере, поэтому он не должен зависеть ни от React, ни от браузерных API.
- Раз V1 уже Mini App, **`telegram_id` известен с первого дня** — переход на V2 не потребует ни экспорта файлов, ни ручной миграции.

### Осознанный компромисс

CloudStorage работает через клиент Telegram, поэтому **полноценного offline-режима в V1 не будет**. Взамен — синхронизация между устройствами и устойчивость к очистке кеша, без единой строчки бэкенда. Для приложения, живущего внутри Telegram (которому связь нужна в любом случае), это разумный обмен.

## Стек

| Слой | Выбор | Почему |
|---|---|---|
| Фреймворк | Next.js (App Router), `output: 'export'` | Серверной логики нет; статика убирает cold start. Mini App — это просто веб-страница в webview Telegram |
| Хостинг | Vercel | URL страницы прописывается в BotFather как Mini App. Позже можно консолидировать на Cloudflare Pages вместе с V2 — разница непринципиальна |
| Telegram SDK | `@telegram-apps/sdk-react` | Поддерживаемая обёртка над `telegram-web-app.js`: промисифицированный CloudStorage, типы, хуки на themeParams/viewport |
| Хранилище | Telegram CloudStorage | Без бэкенда, но с синхронизацией между устройствами и без потери при очистке кеша |
| State | Zustand + гидратация при старте | Zustand — источник для UI, CloudStorage — источник правды на диске |

## Интеграция с Telegram

- **`themeParams` → CSS-переменные.** Приложение автоматически совпадает с темой клиента (светлая/тёмная), ничего своего не навязываем.
- **`BackButton`** — нативная навигация назад вместо собственной кнопки в интерфейсе.
- **`MainButton`** — основное действие экрана (в Add Deed: «Записать дело»).
- **`HapticFeedback`** — тактильный отклик на начисление баллов и особенно на level-up. Дешёвый и очень заметный вклад в ощущение геймификации.
- **`expand()` при старте + `disableVerticalSwipes()`** — иначе скролл списка дел закрывает приложение случайным свайпом.
- **Safe areas / `viewportStableHeight`** — иначе контент уезжает под клавиатуру и системные панели.

**initData в V1 не валидируем.** Валидировать нечем и незачем: сервера нет, защищать нечего. Из `initData.user` берём только имя и аватар для отображения. Проверка HMAC появляется в V2 вместе с бэкендом.

## Модель данных

```ts
type DeedCategory =
  | "helping_person" | "animal_care" | "environment" | "volunteering"
  | "donation" | "kindness_gesture" | "self_improvement" | "other";

type EffortLevel = 1 | 2 | 3; // small / medium / large

interface Deed {
  id: string;              // короткий nanoid
  description: string;     // заметка; на баллы НЕ влияет; лимит ~140 символов
  category: DeedCategory;
  effortLevel: EffortLevel;
  karmaPoints: number;
  createdAt: number;       // epoch seconds (компактнее ISO)
}

interface KarmaState {
  totalKarma: number;
  level: number;
  currentLevelXp: number;
  xpToNextLevel: number;
  updatedAt: number;
}

interface Streak {
  currentStreak: number;   // подряд идущих дней с ≥1 делом
  longestStreak: number;
  lastDeedDate: string;    // YYYY-MM-DD
}

interface Badge {
  code: string;
  earnedAt: number;        // title/description — в статическом каталоге в коде
}
```

Поля намеренно компактны (`createdAt` числом, а не ISO-строкой; у бейджа только код) — всё это едет в CloudStorage, где значение ограничено 4096 символами.

## Раскладка в CloudStorage

Лимиты API: **1024 ключа**, ключ ≤128 символов, значение ≤4096 символов. Требуется Bot API 6.9+.

| Ключ | Содержимое |
|---|---|
| `meta` | `schemaVersion`, `deedCount`, номер последнего чанка |
| `state` | `KarmaState` + `Streak` + список заработанных бейджей (сильно меньше 4 КБ) |
| `d0`, `d1`, … | чанки дел, ~20 дел на чанк |

**Компактная сериализация**: короткие имена полей, категория — индексом, время — epoch seconds. Один deed ≈ 200 байт, значит ~20 дел в чанк, а 1024 ключа дают потолок примерно **20 000 дел** — на годы вперёд.

### Стратегия чтения и записи

- **Запись**: при добавлении дела переписываем только «горячий» последний чанк и `state` → **2 записи на дело**. Старые чанки иммутабельны. Когда чанк подходит к 4096 символам — заводим следующий.
- **Чтение**: на старте читаем только `meta` + `state` → Home рисуется мгновенно. Чанки дел грузим лениво, при открытии History, батчем через `getItems`.
- **Конкурентность**: транзакций нет, семантика last-write-wins. Для однопользовательского трекера риск мал; перед записью перечитываем `meta`, чтобы не затереть чанк, добавленный со второго устройства.
- **Fallback**: если CloudStorage недоступен (старый клиент), уходим в `localStorage` с тем же интерфейсом и показываем баннер «данные хранятся только на этом устройстве». Кода немного, а иначе приложение просто не работает у части пользователей.

## Начисление баллов (без AI)

`karmaPoints = вес категории × множитель усилия` — два тапа, текст не парсим. Свободное описание остаётся только заметкой в истории, чтобы не тащить в V1 никакой оценки текста.

| Категория | Вес |
|---|---|
| volunteering | 15 |
| donation | 12 |
| helping_person | 10 |
| animal_care | 10 |
| environment | 8 |
| self_improvement | 6 |
| kindness_gesture | 5 |
| other | 5 |

| Усилие | Множитель |
|---|---|
| Small (≤15 мин) | ×1 |
| Medium (~час) | ×2 |
| Large (значимое время) | ×3 |

Диапазон — **5–45 баллов** за дело. В V2 это же число становится `base_score`: подсказкой рецензенту, от которой он отталкивается при своей оценке.

## Кривая уровней

Порог входа на уровень: **`minXp(N) = 25 × (N−1) × N`** — квадратичный рост, классическая RPG-кривая: быстро в начале, ощутимо медленнее дальше.

| Ур. | XP | Титул |
|---|---|---|
| 1 | 0 | Искра |
| 2 | 50 | Огонёк |
| 3 | 150 | Свет |
| 4 | 300 | Доброе сердце |
| 5 | 500 | Хранитель |
| 6 | 750 | Наставник |
| 7 | 1050 | Вдохновитель |
| 8 | 1400 | Светоч |
| 9 | 1800 | Мудрец |
| 10 | 2250 | Просветлённый |

При среднем деле ~15 очков: уровень 2 достигается за 3–4 дела, уровень 5 — за ~33, уровень 10 — за ~150. Прогресс растянут на месяцы. Выше 10 формула продолжается; титул — «Просветлённый ур. N» либо отдельный список названий каждые 5 уровней.

**Level-up**: пересчёт кармы → поиск уровня по таблице порогов → анимация + `HapticFeedback.notificationOccurred('success')` → обновление прогресс-бара.

## Стрики и бейджи

**Streak**: +1, если дело добавлено в календарный день, следующий за `lastDeedDate`. Несколько дел в один день не считаются повторно. Пропуск дня → сброс `currentStreak`, при этом `longestStreak` сохраняется.

**Бейджи**: `first_deed`, `streak_7`, `streak_30`, `deeds_10/50/100/500`, `level_5`, `level_10`, `category_collector` (хотя бы одно дело в каждой категории).

**Визуальная обратная связь**: прогресс-бар кармы на Home, тост «+X кармы» при добавлении, сетка бейджей с открытыми и закрытыми, опционально heatmap-календарь как у GitHub-контрибуций.

## Экраны

1. **Home** — карма, уровень + титул, прогресс-бар до следующего уровня, streak, MainButton «Добавить дело», последние 5 дел.
2. **Add Deed** — описание, категория (иконки), усилие (3 кнопки) → анимация начисления, возможный level-up.
3. **History** — список с ленивой подгрузкой чанков, фильтр по категории, heatmap-календарь.
4. **Profile** — кривая уровней, бейджи, статистика по категориям и стрикам, сброс данных.

## Настройка бота

BotFather: `/newbot` → `/newapp` (или Menu Button) → URL Mini App.

Для разработки — туннель (`cloudflared` / `ngrok`) на локальный dev-сервер. Для отладки на мобильном подключить `eruda`: консоль в webview иначе недоступна.

## Порядок реализации

1. **`lib/karma/scoring.ts`** — веса категорий, множители усилия, кривая уровней, поиск уровня по XP. Единственный источник правды о баллах; в V2 переиспользуется Worker'ом, поэтому без зависимостей от React и браузера.
2. **`lib/storage/cloudStorage.ts`** — обёртка над CloudStorage: чанкование, компактная сериализация, ленивое чтение, fallback на `localStorage`.
3. **`lib/telegram/init.ts`** — инициализация SDK, `expand()`, `disableVerticalSwipes()`, themeParams → CSS-переменные, BackButton/MainButton.
4. Zustand store + гидратация, экраны Home / Add Deed / History / Profile.
5. Стрики, бейджи, level-up анимация + haptics.
6. Бот в BotFather, деплой на Vercel, привязка URL.

## Верификация

Отлаживать в реальном Telegram через туннель — webview заметно отличается от обычного браузера.

- Добавить дела всех категорий и усилий → сверить начисленные баллы с таблицей весов вручную.
- Пройти пороги 50 / 150 / 300 XP → level-up срабатывает ровно один раз на порог, прогресс-бар не уезжает.
- **Streak**: дело сегодня, затем перевод системной даты на +1 день → streak 2; на +3 дня → сброс в 1, `longestStreak` сохранён.
- **CloudStorage**: добавить >20 дел → убедиться, что завёлся второй чанк, а старый не переписывается (следить за числом вызовов записи). Закрыть и открыть Mini App → состояние восстановилось.
- **Синхронизация**: открыть Mini App на втором устройстве под тем же аккаунтом → те же дела и карма.
- **Fallback**: замокать отсутствие CloudStorage → приложение работает на `localStorage` и показывает баннер.
- **Тема**: переключить Telegram между светлой и тёмной → интерфейс следует за клиентом, нечитаемых мест нет.
- **Клавиатура и safe areas** на реальном мобильном: поле ввода не перекрыто, свайп по списку не закрывает приложение.
