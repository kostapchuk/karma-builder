# Karma Builder — V2

Трекер добрых дел, в котором баллы ставит **не автор**. Записал дело → отправил
одноразовую ссылку → её открыл кто-то другой и оценил → карма выросла на среднее
оценок. Ссылка ведёт в само приложение: рецензент опознан, поэтому подтвердить
своё же дело нельзя.

- [docs/v1-mini-app.md](./docs/v1-mini-app.md) — замысел V1
- [docs/v1-status.md](./docs/v1-status.md) — что было построено в V1
- [docs/v2-reviews.md](./docs/v2-reviews.md) — план V2
- [docs/v2-status.md](./docs/v2-status.md) — **что реально построено**: расхождения с планом,
  что проверено и что нужно сделать руками для прода

## Три части

| Часть | Что это | Где живёт |
|---|---|---|
| **Mini App** | тот же интерфейс, что в V1, плюс ревью и лидерборды | Next.js, статический экспорт → Worker `karma-builder-app` |
| **API** | вся логика и данные | Cloudflare Workers + D1 → `workers/` |
| **Экран рецензента** | шкала оценки с якорями | `app/rate/` внутри Mini App |

Статика раздаётся Worker'ом, а не Cloudflare Pages: зона `pages.dev` режется
частью провайдеров — подмена DNS и обрыв по SNI. Подробности — в
[docs/v2-status.md](./docs/v2-status.md#почему-не-pages).

Оценка живёт **внутри** Mini App, а не на отдельной странице без логина: иначе
сервер не знает, кто ставит балл, и автор подтверждает собственное дело сам.
Ссылка на ревью — deep-link `t.me/<bot>?startapp=r<token>`.

Карма начисляется **только** сервером и **только** после оценок посторонних. Клиент её не считает —
он показывает то, что вернул API.

## Запуск

Нужны два процесса. Порядок важен: Mini App ходит в Worker.

```bash
npm install
cp .env.example .env.local                       # адрес API + токен для дев-мока
cp workers/.dev.vars.example workers/.dev.vars   # BOT_TOKEN для локальной валидации

npm run db:migrate:local   # создать локальную D1
npm run dev:api            # Worker на :8788
npm run dev                # Mini App на :3000
```

Экран оценки — часть приложения: `/rate/?t=<token>`. Токен для проверки руками
берётся из ответа `send-review` или прямо из локальной базы.

Вне Telegram приложение поднимает дев-мок клиента. В отличие от V1, мок теперь **по-настоящему
подписывает `initData`** локальным токеном — иначе Worker отвечал бы 401 на каждый запрос.
Токен в `.env.local` и в `workers/.dev.vars` должен совпадать.

Отладка в живом клиенте: туннель (`cloudflared` / `ngrok`) на :3000, URL из туннеля
в BotFather, `NEXT_PUBLIC_API_BASE_URL` — на публичный адрес Worker'а.

## Проверки

```bash
npm test           # чистое ядро: баллы, уровни, стрики, бейджи, сериализация (31)
npm run test:api   # Worker без сети: auth, прогресс, токены (19)
npm run test:e2e   # живой wrangler dev + D1: весь API целиком (21)
npm run typecheck  # приложение и Worker
npm run build      # статический экспорт в out/
```

`test:e2e` поднимает Worker сам и чистит локальную базу перед прогоном. Именно там проверяются
вещи, которые моком не проверишь: одноразовость ссылки под гонкой, однократность начисления
кармы и то, что автор не может подтвердить собственное дело.

## Структура

| Что | Где |
|---|---|
| Баллы, кривая уровней, титулы | `lib/karma/scoring.ts` |
| Стрики, бейджи | `lib/karma/streak.ts`, `lib/karma/badges.ts` |
| Якоря и потолок оценки рецензента | `lib/karma/review.ts` |
| Клиент API, типы ответов | `lib/api/` |
| Telegram SDK, share, дев-подпись initData | `lib/telegram/` |
| Экраны | `app/` — Home, `add`, `review`, `rate`, `history`, `leaderboard`, `profile`, `friend` |
| Схема и миграции D1 | `workers/migrations/` |
| Валидация initData | `workers/src/auth/telegramAuth.ts` |
| Маршруты API | `workers/src/routes/` |
| Шкала оценки | `components/ReviewScale.tsx` |

`lib/karma/*` не зависит ни от React, ни от браузерных API — **тот же код** считает баллы
в Worker'е. Копий весов и кривой уровней на сервере нет.

## Как устроено ревью

```
дело (pending) ──send-review──> токен на слот, 32 символа, живёт 72 часа
                                       │
                    t.me/<bot>?startapp=r<token>
                                       │
                          Mini App, рецензент опознан
                                       │
                                  оценка 0–50
                                       ▼
                    final_score = среднее, статус approved,
                         karma_total += final_score
```

Сколько нужно оценок — задаёт `REVIEWER_SLOTS` в `lib/karma/review.ts`. Сейчас
одна; от длины этого списка зависят и число ссылок, и порог перевода
в `approved`.

Четыре инварианта, и первые два живут в SQL, а не в коде:

- **по одной ссылке засчитывается ровно одна оценка** — условие «токен свободен» встроено
  в саму вставку оценки (`INSERT ... SELECT ... WHERE used_at IS NULL`), поэтому между
  проверкой и записью нельзя вклиниться;
- **карма за дело начисляется ровно один раз** — начисление и перевод дела в `approved`
  идут одним батчем и оба условны по прежнему статусу дела;
- **автор не оценивает своё дело** — сравнение с `deed.user_id` на обоих маршрутах;
- **один человек не оценивает одно дело дважды** — уникальный индекс
  `(deed_id, reviewer_user_id)`, а не только проверка в коде.

Все проверены тестами, первые два — с одновременными запросами.

## Одна шкала кармы

`karma_total` — и она подтверждённая. Записанное дело баллов не даёт, пока его не
оценил кто-то посторонний, поэтому накрутить рейтинг в одиночку нельзя
по построению.

Самооценка и перенос истории V1 были и убраны (миграция `0003`): вторая шкала
рядом с подтверждённой только путала. Баллы V1 остались в CloudStorage
нетронутыми — приложение их больше не читает.

## Деплой

Инфраструктура поднята, секретов в репозитории нет: `BOT_TOKEN` живёт в
`wrangler secret`, локально — в `workers/.dev.vars`.

```
npm run deploy:api    # API + D1
npm run deploy:app    # Mini App; адрес API вшивается на сборке:
                      # NEXT_PUBLIC_API_BASE_URL=<домен API> npm run deploy:app
```

Две ручки закрытого запуска: `MAX_USERS` в `workers/wrangler.jsonc` (потолок
регистраций) и `REVIEWER_SLOTS` в `lib/karma/review.ts` (сколько оценок нужно
делу). Что именно развёрнуто и что делалось руками —
в [docs/v2-status.md](./docs/v2-status.md#что-развёрнуто).

`AGENTS.md` и `CLAUDE.md` в корне генерирует сам `next dev` — это не ручные файлы.
