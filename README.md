# Karma Builder — V1

Telegram Mini App для трекинга добрых дел: записал дело → получил баллы кармы → вырос в уровне.
Бэкенда нет, данные живут в Telegram CloudStorage. Полное описание замысла — в [docs/v1-mini-app.md](./docs/v1-mini-app.md).

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # чистое ядро: баллы, уровни, стрики, бейджи, сериализация
npm run build      # статический экспорт в out/
```

Вне Telegram приложение поднимает дев-мок клиента: тема, viewport и `initData` подставляются,
а CloudStorage сознательно не мокается — приложение уходит на `localStorage` и показывает баннер.
Так путь фолбэка проверяется на каждом запуске.

Для отладки в реальном клиенте нужен туннель на dev-сервер (`cloudflared` / `ngrok`) и URL
из туннеля в BotFather: `/newbot` → `/newapp` → URL Mini App. На мобильном консоль webview
недоступна — подключайте `eruda`.

## Структура

| Что | Где |
|---|---|
| Баллы, кривая уровней, титулы | `lib/karma/scoring.ts` |
| Стрики | `lib/karma/streak.ts` |
| Бейджи (каталог + условия) | `lib/karma/badges.ts` |
| Компактная сериализация, лимиты чанка | `lib/storage/codec.ts` |
| CloudStorage / localStorage | `lib/storage/driver.ts` |
| Чанкование, чтение и запись | `lib/storage/repository.ts` |
| Инициализация Telegram SDK | `lib/telegram/init.ts` |
| Zustand store | `lib/store/useAppStore.ts` |
| Экраны | `app/page.tsx`, `app/add`, `app/history`, `app/profile` |

`lib/karma/*` не зависит ни от React, ни от браузерных API — в V2 этот же код
переиспользует серверный Worker.

## Раскладка в CloudStorage

| Ключ | Содержимое |
|---|---|
| `meta` | `schemaVersion`; пишется один раз |
| `state` | карма, стрик, бейджи, счётчики по категориям, `deedCount`, номер последнего чанка |
| `d0`, `d1`, … | чанки дел, до 25 штук или ~3.8 КБ на чанк |

- **Запись дела** — 2 вызова: горячий чанк + `state`. Старые чанки иммутабельны.
- **Чтение на старте** — `state` + горячий чанк, чтобы Home рисовался сразу.
  Остальные чанки грузятся лениво при открытии History.
- Перед записью `state` перечитывается: транзакций нет, семантика last-write-wins.

Отличие от плана: счётчики `deedCount` и номер последнего чанка лежат в `state`, а не в `meta`.
В плане они были в `meta`, но тогда на каждое дело приходилось бы три записи вместо заявленных
двух — `meta` меняется вместе со `state` на каждое дело. `meta` остался маркером схемы для
будущих миграций.

## Устойчивость хранилища

`cloudStorage.isAvailable()` отвечает по версии клиента и этого мало: часть клиентов Telegram
не отвечает на custom-методы вовсе. Поэтому у каждого запроса есть таймаут (5 с), а первый же
отказ или таймаут переводит приложение на `localStorage` до конца сессии и поднимает баннер.
Без этого приложение зависало бы на сплэш-экране — проверено на практике при разработке.

## Что проверено

Автоматически (`npm test`, 31 проверка):

- баллы по всем парам категория × усилие укладываются в 5–45 и совпадают с таблицей весов;
- `levelForXp` обратна порогам на каждом уровне до 60-го, уровень растёт монотонно и без скачков;
- стрик: тот же день, следующий день, пропуск, протухание, границы месяцев;
- бейджи выдаются один раз и все достижимы;
- чанк, набитый по правилу `chunkFits`, всегда влезает в лимит значения — включая худший случай
  с описаниями в 140 символов (там чанк закрывается по длине, не добирая до 25 дел);
- битые `state` и чанки читаются как пустые, а не роняют приложение.

Вручную в браузере (дев-мок, хранилище — `localStorage`):

- Волонтёрство × Large даёт ровно +45; карма, стрик, счётчик дел и бейдж «Первый шаг» обновляются;
- пороги 50 и 150 XP: level-up срабатывает один раз на порог, оверлей показывается, прогресс-бар
  не уезжает;
- History грузит историю, фильтры по категориям и heatmap работают; Profile показывает бейджи,
  статистику и кривую уровней;
- состояние переживает перезагрузку страницы;
- баннер фолбэка появляется, когда CloudStorage недоступен.

Осталось проверить в реальном Telegram (webview заметно отличается от браузера):

- синхронизация между двумя устройствами под одним аккаунтом;
- переход через границу чанка: >25 дел заводят второй чанк, старый не переписывается;
- нативные MainButton / BackButton и haptics;
- переключение светлой и тёмной темы клиента;
- клавиатура и safe areas на мобильном; свайп по списку не закрывает приложение.
