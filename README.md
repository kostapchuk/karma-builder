# Karma Builder — V2

Трекер добрых дел, в котором баллы ставит **не автор**. Записал дело → отправил двум людям
одноразовые ссылки → они независимо оценили → карма выросла на среднее их оценок.
Рецензентам не нужен ни аккаунт, ни Telegram: ссылка открывается в любом браузере.

- [docs/v1-mini-app.md](./docs/v1-mini-app.md) — замысел V1
- [docs/v1-status.md](./docs/v1-status.md) — что было построено в V1
- [docs/v2-reviews.md](./docs/v2-reviews.md) — план V2
- [docs/v2-status.md](./docs/v2-status.md) — **что реально построено**: расхождения с планом,
  что проверено и что нужно сделать руками для прода

## Три части

| Часть | Что это | Где живёт |
|---|---|---|
| **Mini App** | тот же интерфейс, что в V1, плюс ревью и лидерборды | Next.js, статический экспорт → Vercel |
| **API** | вся логика и данные | Cloudflare Workers + D1 → `workers/` |
| **Страница рецензента** | одна публичная страница со шкалой оценки | Vite + React → Cloudflare Pages, `reviewer/` |

Карма начисляется **только** сервером и **только** после двух оценок. Клиент её не считает —
он показывает то, что вернул API.

## Запуск

Нужны три процесса. Порядок важен: Mini App и страница рецензента ходят в Worker.

```bash
npm install
cp .env.example .env.local                       # адрес API + токен для дев-мока
cp workers/.dev.vars.example workers/.dev.vars   # BOT_TOKEN для локальной валидации

npm run db:migrate:local   # создать локальную D1
npm run dev:api            # Worker на :8788
npm run dev                # Mini App на :3000

cd reviewer && npm install && npm run dev        # страница рецензента на :5173
```

Вне Telegram приложение поднимает дев-мок клиента. В отличие от V1, мок теперь **по-настоящему
подписывает `initData`** локальным токеном — иначе Worker отвечал бы 401 на каждый запрос.
Токен в `.env.local` и в `workers/.dev.vars` должен совпадать. CloudStorage по-прежнему
сознательно не мокается: приложение уходит на `localStorage`, и этот путь проверяется
на каждом запуске — именно из него читает импорт истории V1.

Отладка в живом клиенте: туннель (`cloudflared` / `ngrok`) на :3000, URL из туннеля
в BotFather, `NEXT_PUBLIC_API_BASE_URL` — на публичный адрес Worker'а.

## Проверки

```bash
npm test           # чистое ядро V1: баллы, уровни, стрики, бейджи, сериализация (31)
npm run test:api   # Worker без сети: auth, прогресс, токены (22)
npm run test:e2e   # живой wrangler dev + D1: весь API целиком (21)
npm run typecheck  # приложение и Worker
npm run build      # статический экспорт в out/
```

`test:e2e` поднимает Worker сам и чистит локальную базу перед прогоном. Именно там проверяются
вещи, которые моком не проверишь: одноразовость ссылки под гонкой, однократность начисления
кармы и то, что импорт V1 не двигает лидерборд.

## Структура

| Что | Где |
|---|---|
| Баллы, кривая уровней, титулы | `lib/karma/scoring.ts` |
| Стрики, бейджи | `lib/karma/streak.ts`, `lib/karma/badges.ts` |
| Якоря и потолок оценки рецензента | `lib/karma/review.ts` |
| Клиент API, типы ответов | `lib/api/` |
| Чтение истории V1 для импорта | `lib/storage/legacy.ts` |
| Telegram SDK, share, дев-подпись initData | `lib/telegram/` |
| Экраны | `app/` — Home, `add`, `review`, `history`, `leaderboard`, `profile`, `friend` |
| Схема и миграции D1 | `workers/migrations/` |
| Валидация initData | `workers/src/auth/telegramAuth.ts` |
| Маршруты API | `workers/src/routes/` |
| Страница рецензента | `reviewer/src/` |

`lib/karma/*` не зависит ни от React, ни от браузерных API — **тот же код** считает баллы
в Worker'е. Копий весов и кривой уровней на сервере нет.

## Как устроено ревью

```
дело (pending) ──send-review──> 2 токена по 32 символа, живут 72 часа
                                       │
                     ссылка 1 ─────────┴───────── ссылка 2
                         │                            │
                    оценка 0–50                  оценка 0–50
                         └──────────┬─────────────────┘
                                    ▼
                    final_score = среднее, статус approved,
                         karma_total += final_score
```

Два инварианта, на которых всё держится, и оба живут в SQL, а не в коде:

- **по одной ссылке засчитывается ровно одна оценка** — условие «токен свободен» встроено
  в саму вставку оценки (`INSERT ... SELECT ... WHERE used_at IS NULL`), поэтому между
  проверкой и записью нельзя вклиниться;
- **карма за дело начисляется ровно один раз** — начисление и перевод дела в `approved`
  идут одним батчем и оба условны по прежнему статусу дела.

Оба проверены тестами с одновременными запросами.

## Две шкалы кармы

- `karma_total` — подтверждённая ревью. **Только она** идёт в лидерборды.
- `karma_self_total` — самооценённая, перенесённая из V1.

История V1 импортируется автоматически при первом запуске: клиент читает CloudStorage
и один раз отправляет дела в `/api/import/legacy`. Они ложатся со статусом
`legacy_unverified` и попадают в самооценку. Иначе накрученные локальные баллы «отмывались»
бы в глобальный рейтинг, и смысл ревью терялся бы. Повторный импорт невозможен: решает
серверный флаг `users.legacy_imported_at`, а не отметка на устройстве.

## Деплой

Инфраструктура не поднята: ни `database_id`, ни секретов в репозитории нет.
Пошаговый порядок — в [docs/v2-status.md](./docs/v2-status.md#что-нужно-сделать-руками-для-прода).
Коротко: создать D1 → положить `BOT_TOKEN` в секреты Worker'а → задеплоить Worker →
собрать и задеплоить `reviewer/` на Pages → прописать домены друг другу → задать
`NEXT_PUBLIC_API_BASE_URL` на Vercel.

`AGENTS.md` и `CLAUDE.md` в корне генерирует сам `next dev` — это не ручные файлы.
